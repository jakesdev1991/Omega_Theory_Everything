# Make AXLE MCP Active in Hermes Agent

## Important distinction

This setup runs the **AXLE MCP adapter locally as a stdio subprocess**, but AXLE's
metaprogramming engine remains a hosted service and requires internet access plus an AXLE API
key. Your `lean_verify_local` server remains the offline/local strict verifier.

For a practical proof-development stack, register all three:

| Hermes MCP server | Runs where | Purpose |
|---|---|---|
| `axle` | local adapter → AXLE cloud | extraction, transformation, proof-state batches, AXLE verification |
| `lean_lsp` | entirely local | interactive goals, diagnostics, local theorem search |
| `lean_verify_local` | local Docker | final adversarial declaration/signature/kernel verification |

## Why AXLE often does not appear

Hermes does **not** use Claude's JSON key `mcpServers`. Hermes reads the top-level YAML key
`mcp_servers` from the active profile's `config.yaml`. It also uses profile-specific paths,
so editing `~/.hermes/config.yaml` does nothing if Hermes is running another profile.

Always discover the actual files with:

```bash
hermes config path
hermes config env-path
```

For a named profile:

```bash
hermes --profile NAME config path
hermes --profile NAME config env-path
```

## Prerequisites

1. Update or inspect Hermes:

```bash
hermes version
hermes update --check
```

2. Make sure `uv` and `uvx` are visible:

```bash
command -v uv
command -v uvx
uvx --version
```

3. Create an AXLE API key at:

```text
https://axle.axiommath.ai/app/console
```

4. Make sure the local verifier image from the main README is already built.

## Automated configuration—recommended

From this repository:

```bash
uv sync
uv run python scripts/configure_hermes_axle.py
```

The script:

- asks for the AXLE key without echoing it,
- discovers the active Hermes profile's real config and `.env` paths,
- backs up both files,
- stores the key only in `.env` with restrictive permissions,
- writes Hermes-native `mcp_servers` YAML,
- uses absolute `uv`/`uvx` paths so GUI/background Hermes processes can find them,
- registers every AXLE tool without a stale allowlist,
- registers `lean_verify_local`, and
- runs `hermes mcp test` and `hermes mcp list`.

Add local Lean LSP interaction for the Volumes project:

```bash
cd /absolute/path/to/Volumes
lake build

cd /absolute/path/to/lean-local-verifier
uv run python scripts/configure_hermes_axle.py \
  --lean-project /absolute/path/to/Volumes
```

Named Hermes profile:

```bash
uv run python scripts/configure_hermes_axle.py \
  --profile research \
  --lean-project /absolute/path/to/Volumes
```

Configure only AXLE, leaving the existing local-verifier entry untouched:

```bash
uv run python scripts/configure_hermes_axle.py --skip-local-verifier
```

Do not use `--api-key` unless necessary because shell history may record it. By default the
script uses `AXLE_API_KEY` from the environment or prompts securely.

## Manual Hermes configuration

First put this in the active profile's `.env` file shown by `hermes config env-path`:

```dotenv
AXLE_API_KEY=your-real-key
```

Then merge this into the **top level** of the active `config.yaml` shown by
`hermes config path`:

```yaml
mcp_servers:
  axle:
    command: "/absolute/path/from-command-v-uvx"
    args: ["--from", "axiom-axle-mcp", "axle-mcp-server"]
    env:
      AXLE_API_KEY: "${AXLE_API_KEY}"
    enabled: true
    timeout: 300
    connect_timeout: 90
    trust: untrusted
    supports_parallel_tool_calls: false
    tools:
      resources: false
      prompts: false
```

Do not add a `tools.include` filter during initial setup. AXLE generates tools dynamically
from its endpoint list; an old allowlist can make new tools invisible.

Use the complete three-server template in `hermes-config.example.yaml` if desired.

## Test and activate

Run outside an active chat:

```bash
hermes mcp test axle
hermes mcp list
```

A successful test should report a connection and discovered tools. AXLE tools are registered
in Hermes with names such as:

```text
mcp_axle_check
mcp_axle_verify_proof
mcp_axle_extract_proof_states
mcp_axle_simplify_theorems
mcp_axle_repair_proofs
mcp_axle_extract_decls
mcp_axle_read_docs
mcp_axle_list_environments
```

The exact list is generated by the currently deployed AXLE endpoint catalog.

If you previously selected only some tools, reopen Hermes's tool checklist:

```bash
hermes mcp configure axle
```

Select `verify_proof`, `extract_proof_states`, `simplify_theorems`, and any other required
tools. Restart Hermes after configuration. In a UI that supports MCP reload, reloading the MCP
connections is also sufficient.

Start a fresh session for the cleanest tool discovery:

```bash
hermes chat
```

Then ask:

```text
List the available mcp_axle tools. Call mcp_axle_list_environments and report the result.
```

## If AXLE is still missing

### 1. Confirm the active config

```bash
hermes config path
hermes config env-path
hermes config get mcp_servers --json
```

Look specifically for top-level `mcp_servers.axle`. The incorrect paths are:

```text
mcp.servers.axle
mcpServers.axle
servers.axle
```

### 2. Confirm the executable path

Hermes passes a filtered environment to stdio servers. Use the absolute path in YAML:

```bash
command -v uvx
```

Then make sure the YAML `command` exactly matches that output.

### 3. Refresh the AXLE package

```bash
uvx --refresh --from axiom-axle-mcp axle-mcp-server
```

The command normally appears to hang silently. That is expected: a stdio MCP server waits for
JSON-RPC on stdin. Press Ctrl+C after confirming it does not immediately crash.

### 4. Use Hermes's own connection probe

```bash
hermes mcp test axle
```

This is more meaningful than starting the stdio process manually because it initializes MCP,
lists tools, and exercises the same configuration Hermes will use at startup.

### 5. Inspect logs

```bash
hermes logs errors -n 200
hermes logs --component tools --since 30m -n 300
```

Typical messages:

- `No such file or directory: uvx` — use an absolute `command` path.
- missing `AXLE_API_KEY` — key is in the wrong profile's `.env` or interpolation is wrong.
- `401`/`403` — create or replace the AXLE key.
- connection timeout — increase `connect_timeout`, check DNS/firewall, and rerun with
  `uvx --refresh`.
- zero selected tools — run `hermes mcp configure axle` or remove `tools.include`.
- no `mcp_servers` in `hermes dump` — wrong YAML key or wrong profile.

### 6. Update Hermes MCP support

```bash
hermes update --check
hermes update --backup
```

Then rerun the configuration script and restart Hermes.

## Recommended Volumes 1–54 workflow

Use a branch and process one theorem at a time:

1. Locate a `True.intro`, `sorry`, or placeholder declaration.
2. Recover the intended informal statement from the volume text.
3. Formalize that statement as a trusted Lean specification.
4. Run local Lean LSP diagnostics and obtain the exact goal state.
5. Use AXLE `extract_proof_states`, declaration extraction, repair, and transformation tools
   as appropriate.
6. Have Hermes construct a candidate proof using Mathlib lemmas.
7. Compile locally after every small edit.
8. Run AXLE `verify_proof` against the immutable formal statement.
9. Run `lean_verify_local.verify_against_spec` as the independent final check.
10. Commit only after both verifiers pass with no `sorry`, custom axiom, unsafe, or partial
    declaration.

### Critical warning about `True.intro`

If a declaration literally says:

```lean
theorem important_result : True := by
  exact True.intro
```

then the **statement itself is a placeholder**. Replacing only `True.intro` cannot create the
intended mathematics because Lean is currently being asked to prove only `True`. First replace
`: True` with the actual formal proposition based on the volume's specification, and review that
statement independently. AXLE can verify a proof of a formal statement; it cannot determine by
itself whether that formal statement faithfully captures the prose.

Also note the roles of the AXLE tools:

- `extract_proof_states` extracts obligations; it does not automatically solve all of them.
- `simplify_theorems` prunes/simplifies existing proofs; it is not a general theorem prover.
- `verify_proof` validates a candidate against a trusted statement; it does not invent the
  proof.

Hermes plus local Lean LSP performs the iterative proof construction; AXLE and the local verifier
provide transformation and independent verification.
